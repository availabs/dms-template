What this pass found

The link work landed

Of the 19 dead links a planner could reach in v2, one is left: CREATE on /admin/forms/participation/view still points at /admin/forms/participation/create, a page that has since been deleted. The Forms hub no longer advertises a page that was never built, the two mis-named Capabilities links are gone with the page that held them, and on the county side both LHMP_IA rows v2 flagged now resolve — with one row it did not flag still broken.

The buttons did not

The dead CREATE targets were removed rather than rewired. 21 CREATE buttons now carry an empty target, which renders as a link to the current page — confirmed live on /admin/forms/actions, whose CREATE anchor is href="/admin/forms/actions". On the annex page, thirteen “Add New …” buttons are anchored to #. 23 pages carry a fully-built create modal; nothing in the pattern can open one.

Why nobody has noticed

The deployed bundle (index-CQNxZA8R.js, 2194 KB) predates modal section groups. It renders every create group as an ordinary band, so the add form sits permanently visible below the table and creating rows works today. The same bundle has no fetchMode either. The next deploy activates both at once: every create form disappears behind a modal nothing can open, and 136 data components start honouring a fetch mode they have never been given.

What the deployed build actually supports

Checked by fetching the served bundle and searching it for each configuration key. This decides which findings are live today and which are latent until the next deploy — and it is the single most important piece of sequencing information in this report.

Present in index-CQNxZA8R.js

allowAdddNew addNewBehaviour navigateUrlOnAdd readyToLoad usePageFilters edit-section

Add-new forms, the navigate-on-add behaviour, the older readyToLoad loader gate and page filters all work in production today.

Absent from the bundle

Modal section groups, action params (so no create modal can open, and ?create=1 cannot open one either), data-refresh subscribers, and the whole fetch-mode selector.

The one gap

Progress (published 2379972 / draft 2334420) is the only LHMP_IA box with no section permissions. Set the same grant on both copies.

Two locks on the wrong boxes

(untitled) (2379900) and Problem Areas (2379937) carry the template-editor grant but read Jurisdictions — county-authored prose. Problem Areas in particular is a box the planner is meant to fill in.

What the grant enforces

Section permissions merge onto the pattern's, they do not replace them (utils/auth.js · mergeAuthPermissions), and they gate the section's edit chrome (canEditSection), not visibility. Pattern 566466 already grants LHMP Template Editor: ["*"] and AVAIL: ["*"], and gives DHSES and LHMP Admin Group only view-page. So today the grant is documentation, not enforcement. To restrict a box to only template editors, the section override must also disable the other grants with empty arrays.

Method, and what is not covered

How the numbers were produced

Every page and section of pattern 566466 (72 pages, 1,023 sections) and county_template 1300890 (58 pages, 3,867 sections) was fetched through the CLI's falcor client on 2026-08-14 and written to JSON.
