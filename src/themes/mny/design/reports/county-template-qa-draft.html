3 · 58 data components store a row count of exactly zero

Every one of the 58 carries a filter block, and every one stores totalLength: 0 with no cached rows — not null, but a zero that was computed and written. On a published plan these are the sections a reader meets as a heading with nothing under it, or as a pager reading Page 1 of 0.

Spread across 19 of the 26 pages. Recurring sources: Hazards_of_Concern, Capabilities_Catalogue, AVAIL — Fusion Events V2.

Caveat, and it matters: totalLength is a cached count written at save time, not a live query result. A stored zero can mean the subject genuinely has no rows, or that the filter no longer matches, or simply that the count was written before the data arrived. These three have identical config and opposite fixes. This finding is a triage list, not a defect list.

Tier 2

5 · 190 sections still carry no requirement tag — but 49 of them are page headers and footers

After removing the 324 in-scope tag-exempt ids and the 10 hidden sections, 190 remain untagged. 49 of those are the banner and footer strips that frame a page — Header: MNY Data (25) and Footer: MNY Footer (24). Requirement tags name 44 CFR 201.6 elements, and a page header does not satisfy any part of the federal requirement, so there is no correct tag to give it. Those 49 will read as untagged in every future run of this check and nobody can ever close them.

Tier 2

6 · 192 data components bind a source that no longer resolves

Of the 820 draft sections that bind a source, 192 point at a source id with no row behind it — 15 distinct legacy numeric ids (870 alone carries 138 components, then 1508×32, 1651×8, and eleven more with 1–2 each).

These are not necessarily broken — they are most likely DaMa-side sources living outside this app’s tables. But nothing in this report can assess them: no snapshot check, no column drift, no source-side reasoning. That is a 23% hole in the coverage of every data finding above, and it should be closed before anyone reads a clean result as a complete one.

Tier 3

8 · The template runs two config generations at once

458 v1 and 362 v2 among the 820 data components. The library treats this as a transition — buildUdaConfig.js:1775 is an explicit “temporary adapter” mapping sourceInfo → externalSource and dataRequest.filterGroups → filters at read time, so both render correctly.

It is Tier 3 for a reader and Tier 1 for tooling: finding 1 exists only because a maintenance script assumed one shape. Any script that reads component config must handle both, and any count that doesn’t say which shapes it covered is not yet a complete count. Opening and saving a v1 component migrates it — verified on 1515016.
