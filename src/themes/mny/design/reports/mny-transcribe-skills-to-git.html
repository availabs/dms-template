The verdict

The move is easy.
What the skills point at
is the hard part.

Five files carry reusable method and belong in git. Copying them is a ten-minute job, and only 26 path references need rewriting — most of them one-line. One of those edits fixes a bug that is already wrong today: context/scripts/docx_outline2.py has never existed at that path; the script lives under suffolk/context/scripts/.

The real issue is that these skills are only about 60 % procedure. The other 40 % is “run build_payloads.mjs,” “see suffolk/ANNEX_LOAD_REPORT.md for a worked example,” “the crosswalk CSV is authoritative.” Those 95 scripts and 8 reports stay in the git-ignored folder. A teammate who pulls the repo gets a guide whose every second instruction points at a file they do not have.

So the decision is not which files — that list is settled below. It is how far the blast radius goes: skills only (fast, half-usable), skills + worked-example reports (+88 KB of prose, genuinely teachable), or skills + reports + the scripts (+506 KB, actually runnable by someone else).

Change one thing about the plan

Not tasks/current/
— skills/

planning/planning-rules.md is explicit: everything in tasks/current/ is a task — it carries a **Project:** header, gets a row in the shared todo.md, and is archived to tasks/completed/ when finished. A skill never finishes.

The same file already licenses the alternative: “Project-specific material that isn’t a task (QA process docs, run logs, reference captures) can live directly in the project folder outside tasks/” — the precedent being transportny/qa-process/.

Recommended home

planning/mitigateny/skills/

Same git visibility you asked for, keeps the profiles/ nesting intact, and doesn’t pollute the cross-project index.

Filename convention

Root CLAUDE.md mandates underscores for identifiers; every existing skill filename is hyphenated (authenticating-the-dms-cli.md). Keep hyphens for these docs — flagged only so nobody “corrects” it later. LOADING_PLANS.md is the odd one out and is worth renaming as part of the move.

Red flags

Nine things to know before I touch anything

Tier 1 1 of 9

95 scripts stay behind

suffolk/context/scripts/ (20) · schenectady/context/ (30) · delaware/context/ (16) · mny-1.0-scraper/ (29) — 506 KB of .mjs/.py/.sh. The skills instruct the reader to run them by name. They are all plain text with no data in them, so committing them is cheap; the argument against is that they are county-specific one-offs, not maintained tooling. Decide explicitly — do not let this default silently.

Tier 1 2 of 9

Client plan content enters a shared repo

references/ is git-ignored by design to keep large and licensed source material out. The skills and reports quote consultant plan prose, name real jurisdictions and officials’ roles, and carry live DMS source/view/pattern IDs. That is normal for an internal repo — but this is the moment it stops being local-only, so it deserves one deliberate look. The hard line: no .docx, .pdf, .xlsx or .geojson comes along, ever.

Tier 1 3 of 9

Copy leaves two sources of truth

git mv is unavailable — the source files are untracked, so this is a copy. If the originals survive under references/, the next transcription session edits whichever copy is closer to hand and the two drift within a week. Delete the originals and leave a one-line pointer stub at references/mny-transcribe/skills/README.md — that folder’s CLAUDE.md routes to it and would otherwise dead-end.

Tier 2 4 of 9

The skills index is in a submodule

Root CLAUDE.md tells every agent and teammate to start at src/dms/skills/README.md. That is the @availabs/dms submodule — adding a row means a separate commit in another repo, out of scope here and not something I should do unprompted. Without a second entry point, these skills are committed and still invisible.

Tier 2 5 of 9

tasks/current/ is the wrong shelf

All 16 files there are tasks with a **Project:** header, a row in the shared planning/todo.md, and an eventual move to tasks/completed/. A skill has no completion state, so it either sits in current/ forever misreading as unfinished work, or gets archived and disappears. A profiles/ subfolder inside a task directory is also structurally odd.

Tier 2 6 of 9

A stale section ships with the skill

loading-annexes-into-jurisdictions-dataset.md has a read-path section its own index already marks superseded (dms dataset query now reads split rows anonymously). Committing it is fine — committing it with the warning stripped is not. The warning currently lives in skills/README.md, one file away; move it into the affected section where it cannot be missed.

Tier 3 7 of 9

CLAUDE.md is a magic filename

If any part of references/mny-transcribe/CLAUDE.md ends up under planning/, it must not keep that name — a CLAUDE.md anywhere in the tree is auto-loaded as project instructions for whoever works nearby. Its per-county status table would become standing guidance for unrelated MitigateNY work.

Tier 3 8 of 9

Two task docs need a follow-up line

schenectady-jurisdictional-annexes.md:100 records the skill’s creation at its references/ path, and schenectady-hmp-migration.md:17 points at the git-ignored working folder. Both are already-committed task docs; update the first, leave the second (it correctly describes a local folder).

Tier 3 9 of 9

Nothing here is a Skill-tool skill

These are markdown how-to guides in this repo’s skills/ convention — no SKILL.md, no frontmatter, no .claude/skills/ registration. So the move changes discoverability, not tool availability, and nothing needs re-registering. Worth stating plainly, since “claude skills” means both things in different contexts.
