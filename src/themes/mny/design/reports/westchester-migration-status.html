Point 1, plainly

It’s a dropdown, not content.

additionalSectionAttributes is a pattern-level field that defines one extra editor dropdown on every component in the admin UI. On county_template it defines a field called status with six options. That is a review-workflow label an editor sees next to a box — it is not a section, not content, and it does not render on the public site.

When pattern 2448336 was duplicated this definition didn’t come across, so right now Westchester’s components have no status dropdown at all.

It is not a county_template change. Copying it lands on pattern 2448336 — Westchester’s own pattern — exactly like the geoid 36119 fix you already made. It is post-duplication repair of a field that should have copied and didn’t. C1 does not touch it. If you’d still rather leave it alone, the load simply writes no status and reviewers lose the “which boxes came from the plan” marker. That is the whole cost.

Your instruction caught a real mislabeling. The Schenectady and Delaware loads tagged their fills status: "shmp_sourced_content". For Westchester that label is simply wrong — this prose comes from the county HMP, not the State plan. Had we followed the old convention you would have opened the admin UI to 174 boxes of county content stamped “SHMP Sourced Content”, which is the appearance of exactly what you said never to do. The load convention is now local_review_needed, which is what those boxes genuinely need.
