The create mechanism, accepted as configured

Recorded rather than tracked, so the knowledge survives the decision. Nothing in this section is on the fix list.

How it works today

23 of the 25 in-scope pages carry a section group marked isModal with a modalParamKey, holding a 5–7 field add form. The deployed bundle predates modal section groups, so each of those groups renders as an ordinary band: the add form sits visible below the table and creating rows works. Six families use the key create and land the user on their own single-record editor afterwards; the annex page runs five modals keyed by family name and instead clears the form, closes the modal and publishes the new row id so its tables refresh.

Data fetch mode — full inventory

Force re-fetch and Smart fetch are both acceptable, so this is an inventory rather than a pass/fail sweep. Every component is classified four ways: Force (fetchMode: 'force'), Smart ('smart'), Cache ('cache' — never re-queries), and no setting selected (the key is absent). “Every component” means every component that has the control: it exists on Card, Spreadsheet and Graph only, so Filter and Map sections are noted as having no control rather than counted. Where no setting is selected the loader falls back to readyToLoad === true ? 'smart' : 'cache' (useDataLoader.js:245), which is invisible in the UI — so both the stored setting and the resolved behaviour are shown, and the verdict follows the resolved one.

Method, and what is not covered

How the numbers were produced

All 72 pages and 1,023 sections of pattern 566466 were fetched through the CLI's falcor client on 2026-08-17 and written to JSON. Link targets resolve against the pattern's real slug set. Fetch modes, row-action columns, column bindings and section permissions are read from each section's element-data. Dropped sections are computed by comparing each section's group against its page's declared section_groups, and every other audit filters them out. The scope exclusion of other_forms is asserted in code. Behaviour was verified in a signed-in Chrome session against production. Read-only throughout: nothing was created, edited or deleted, and the row menu was opened but no action clicked.

Not covered

  • High Hazard Dams and everything under other_forms.
