The premise

One home for data entry is a defensible choice — if that home explains itself.

There is a real argument for keeping forms entry in a dedicated panel: one URL to teach, one permission story, a clean separation between "editing the plan" (county pattern, publish workflow) and "entering records" (shared datasets, live effect), and one place DHSES can watch everything. Direction A takes that argument seriously and asks what the panel must become for a non-technical planner to succeed in it.

The July IA report already established the structural answer — one role-adaptive page per page-type per dataset, ~30 pages instead of 112, because auth groups and session geography already decide who sees what. Direction A adopts that collapse wholesale and adds the three things the current-state evidence shows it still lacks: a status front door, working routes in and out of the plan, and a vocabulary planners can read.

The centerpiece · Section 01

Plan Status: the admin panel opens on "here's what's left," not charts of statewide totals

A planner logging in should be oriented in one glance: my county, my plan, my progress, my next task. Every band below is drivable from data that already exists — no new collection, no new schema. (This is the owner-requested status page; in Direction A it doubles as the landing.)

Band 1 · Plan completeness meter

Annotation slots filled vs total (267–276 per county), counted from draft_sections so drafted work counts — Westchester's 54 drafted slots read as progress, not zero. Split by chapter so "Local Environment: 29/32, The Risk: 14/187" tells the planner where to go next.

Band 2 · Form coverage vs the actual rules

Per jurisdiction × per form: row counts scored against the requirements the guide already states — ≥1 action per hazard of concern per jurisdiction, ≥2 new/carryover actions, the SFHA flood-action rule, ~16 HoC determinations per jurisdiction, ≥1 Roles + Participation entry. Red/amber/green per cell; each cell links to the form filtered to the gap.

Band 3 · Requirements crosswalk

LHMP_IA already carries mny_required, control_number (CN…), and cfr_requirement_number per template component — an unused FEMA-element checklist. Rendered as "44 CFR element → where it lives in your plan → filled?", it becomes the pre-review tool Task 7 gestures at.

Band 4 · Where you are in the process

The DHSES_County_Database row (plan status, approval + expiration dates) plus the FEMA Task 1–8 arc, each Task linking to its guide page deep — the contextual wayfinding the current Inline Guidance never wires up. For DHSES logins, this band swaps to the 62-county rollup.

What Direction A cannot fix — read before choosing it

  • The context switch survives. Planners still leave their plan, land in different chrome, and come back. Every measured signal says they resist this — the workflow grew in-plan prototypes and an in-plan actions pattern while the panel sat there.
  • Two paradigms still need teaching. The rewritten guide carries the bridge, but the bridge exists because the architecture demands it — Direction B removes the need instead.
  • Duplication pressure returns. The annex form already lives in both worlds; actions pages exist in three (panel, template, /actions pattern). Consolidating the panel does not resolve which world owns a workflow — it restates the question.

Choose A if build capacity is the binding constraint this cycle. Every deliverable here — the status landing above all — carries forward into Direction B unchanged.
