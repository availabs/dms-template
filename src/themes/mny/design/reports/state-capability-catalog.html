The verdict

Two different tables,
filed as one.

Of 649 rows in the catalog, 402 are real capability programs — each with an administering agency (DEC, DHSES, NYSERDA, FEMA, Red Cross, and dozens more), a description, and its own hazard, funding, and contact metadata. That subset is exactly what you’d expect from a state-level catalog.

The other 247 rows carry no administering agency at all. 245 of those also carry no description, no hazard tag, no funding source, no URL — nothing except a Capability Name. Those names aren’t random text: they’re the same local-jurisdiction capability vocabulary already documented in the Capability Inventory report — “Floodplain Administrator,” “Building Code,” “Mutual Aid Agreements” — each one duplicated 5 to 14 times with zero distinguishing data.

Three more rows are outright test data: “AVAIL TEST ROW,” “Aaaadams 2 Test3,” and one row whose agency field literally reads “TEST.” None of this changes what the 402 real programs say — but it means the table’s row count overstates its actual coverage by well over half again.

That’s a different situation than the 17% partial migration of Capability Category, and worth tracking separately: one is “in progress,” the other hasn’t started.

Recommended path

Clear the placeholders before the catalog scales further

1 · Retire the 248

245 duplicate vocabulary rows plus 3 test rows add zero programs and inflate every “649 capabilities” headline by 62%.

2 · Finish tagging the 402

Only 68 (17%) have a Capability Category; the rest can’t be filtered or reported on by category yet.

3 · Refresh verification dates

Just 1 of 649 rows is confirmed in 2025; 213 haven’t been touched since 2023.

Net effect: the catalog drops from 649 to 402 rows — 38% smaller, and every remaining row is a real program. If those 49 vocabulary terms are meant to stay discoverable, they belong in a capability-type reference list, not duplicated as fake program rows — see the Capability Inventory report, where that same vocabulary is already tracked properly.
