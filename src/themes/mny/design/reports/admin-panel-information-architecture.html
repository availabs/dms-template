The verdict

Geography scoping already exists in the data.
It's just not exposed as a page tier.

Pattern 566466 ("admin", app mitigat-ny-prod) has a single flat Forms hub (page 1336681) with one subtree per dataset. There is no audience-tier concept anywhere in the page tree — every user who reaches /admin/forms sees the same flat list, regardless of whether they work for the state, a county, or a single municipality.

Yet the underlying Actions_Revised source (the live Spreadsheet bound to page 1686224, ~90 columns) already carries geoid_juris and county_geoid — the exact fields a jurisdiction/county/state split would filter on — plus dhses_comments, fema_comments, and approvable, which is a state-level QA/approval workflow with no page anywhere to work it from.

Instead, each dataset evolved its own ad-hoc, incomplete page set. Some ship 10+ variants of the same page-type (single_edit, single_edit_simple, single_edit_new …) with no indication which is current. Five of the seven target datasets have no dashboard or filterable list at all — an author has to already know a record's id to find it.

The proposed fix doesn't invent new capability — it surfaces the tiering the data already supports as role-adaptive scope on one consistently-shaped page per page-type, and fills the gaps (dashboard, spreadsheet-bulk-edit, standalone view) that today's ad-hoc growth skipped. See the "tiers are not pages" callout below for why this is one page per type, not three.

Fields that already exist

geoid_jurisdrives Jurisdiction-role scope
county_geoiddrives County-role scope
approvabledrives State Review
dhses_commentsdrives State Review
fema_commentsdrives State Review

None of these fields have a page today. The State tier's new "State Review" section (Phase 1, shipped) is the first UI to read or write them.

Second look — tiers are not pages

A record doesn't change shape depending on who's looking at it. Only the scope, and a handful of sections, do.

Evidence 1

Pattern 566466's own authPermissions already gate by group (AVAIL, DHSES, LHMP Admin Group…), and the session token carries per-user geography (county_codes). Who-sees-what is already a login-time concern in this platform.

Evidence 2

actions-database.html's own build note: the live page is "filtered to Sullivan County (page param county=36105)... County scope is set at the site level by the page filter param." One template, many counties, via a param — the platform's existing convention.

Evidence 3

An Action's 90 fields are the same 90 fields whether a jurisdiction clerk, a county planner, or a state reviewer opens it. What differs is (a) which records they may see, and (b) whether the State Review section is visible/editable — both role checks, not different content.

Collapses to one page

  • View / Edit / Create — record shape never changes by role
  • Dashboard / Spreadsheet — row scope changes by role/geography; the page doesn't

Stays role-gated within that page

  • Which records are visible (geography/role filter)
  • Extra columns (Jurisdiction, County) for broader-scope roles
  • The State Review section; a jurisdiction-picker field on Create for state-role users
  • Aggregate/rollup sections (e.g. actions-by-county) — a section that's simply empty for narrow scope, not a reason to fork the page

For a static design mockup (no real auth yet), the honest way to show this is a single file per page-type with an in-page "Viewing as: [Jurisdiction / County / State]" toggle that shows/hides the role-gated bits live — not three separate HTML files. This is more useful for review, too: a reviewer sees what changes by flipping one control, instead of diffing three tabs.

Proposed — One Ecosystem Per Dataset, Role-Adaptive

Each dataset's ecosystem was assessed independently against its live field structure — not assumed uniform. Five datasets fit the full 5-page shape naturally; one (High Hazard Dams) is a fixed reference registry that drops Create; one (Capacities) is deferred pending a separate architectural merge into Capabilities. Within each page-type, the three roles below are scope + section visibility, not separate pages — see the "tiers are not pages" callout above.

Jurisdiction role

Sees only one municipality's records. Scoped by geoid_juris — same Dashboard page, filtered.

County role

Sees every jurisdiction in one county. Scoped by county_geoid — same page, a Jurisdiction column/filter simply becomes relevant and renders.

State role

Sees statewide, all counties. Same page, plus a County column/filter and (Actions only, so far) the "State Review" section (approvable / dhses_comments / fema_comments) becoming visible.
