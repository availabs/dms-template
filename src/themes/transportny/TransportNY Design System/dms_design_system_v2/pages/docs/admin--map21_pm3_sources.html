Create the map21 and pm3 sources.

The yearly rebuild behind the MAP-21 PM3 pages and the analytical series: choose the travel-time source and the year, and the platform computes a dataset of per-segment measures from it. Run once a calendar year, in time for the federal filing. This page assumes the year's travel-time data is loaded and complete.

how-to applies to · all products last reviewed · 2026-09-08 owner · — requires an administrator account

What these two datasets are

Both are computed from the travel-time data, one segment at a time; neither is a file anyone uploads. The MAP-21 dataset is the federal one: one calendar year of reliability and delay measures in the column order the federal Highway Performance Monitoring System expects, and the basis of the Travel Time Metrics file New York files with FHWA each June 15. The analytical dataset is the platform's own: the same measures, one version per year, with the extra columns and quality flags the dashboards use. The two are not interchangeable, and the platform's figures are never called federal. PM3 and MAP-21 datasets is the datasheet for both.

One administrator runs this once a year, after the calendar year's travel-time data is complete and before the June filing. The MAP-21 PM3 pages compute their figures live from the dataset it creates, so the year appears on them as soon as the load finishes.

Before you start

Sign in and open the dataset catalog. Creating a dataset needs All (*), the earlier scheme's level 10; adding a year to one that exists needs Create version.

Know three things first: which travel-time source to compute from, since the wrong one silently produces the wrong numbers; which completed calendar year; and whether you are creating a dataset or adding to one — a new federal year is a new version on the existing MAP-21 dataset unless the reporting method has changed.

Set aside time: the load reads a year of travel times for the whole reporting network, and reports in the task log, not on the screen you started it from.

Steps

The federal MAP-21 dataset, one year.

  1. Select Add in the catalog toolbar, then set Type to map21.The panel changes to the MAP-21 inputs.
  2. Enter a Name that says what it is and which year it covers.
  3. Choose the travel-time source in NPMRDS Production Source — the production one, not a test or a partial load.Year becomes usable, limited to the years that source holds.
  4. Set Year to the calendar year you are reporting, and leave % of tmc at 100 — the share of a segment that must have data, and the federal figure is computed at the full share.
  5. Select Add Source.It reads "Publishing...", then the load's task page opens.
  6. Watch the task page: Task:, Status:, Worker: and, while it runs, Progress:, with the events as Event ID · Type · Message · Created At.A failure shows Error: with the reason. Do not start a second load over the same year.
  7. When it finishes, check the version's row count on Overview against the size of that year's reporting network.
  8. Open the MAP-21 PM3 pages, select the new year, and compare the figures with last year's before anyone else does.
  9. To add next year to this dataset rather than creating another, select Add Version on its Admin tab and use the same panel; the button reads Add View there.

The analytical dataset and its years

Same panel, one difference: it takes several years at once, because the dashboards need them together.

  1. Select Add, set Type to pm3, enter a Name, and choose the same NPMRDS Production Source.The Years row fills with one selectable chip per year that source holds.
  2. Select every year you want, and leave % of tmc at 100.
  3. Select Add Source and watch the task page.The load creates one version per year, each named for its four-digit year: three years give three versions.
  4. Next year, use Add Version with just the new year.A new version appears alongside the others, which are untouched.

What you now have

A MAP-21 dataset with one version for the reported year, and an analytical dataset with one version per year. Both are ordinary datasets — description, columns, an Access list, a Tasks log — curated on Manage a dataset. The pages read them live, so check the figures before announcing the year.

Limits and gotchas

  • The button does not appear until a Name, a source and a year are all set.
  • An analytical load cannot append to an existing version: it creates a version per year, and a request that tries to append is refused outright.
  • The two datasets have been separate code paths since August 2026, with a test that fails if the analytical one borrows from the federal one. Never present a platform figure as the submitted one.
  • The earlier procedure had a fourth step, an aggregate dataset built from an analytical one. There is no such data type in this build.
  • A dataset built at anything but 100 % of tmc qualifies a different set of segments, is not comparable with the federal figure, and should say so in its description.
  • The load is long and reports only in the task log. A sleeping browser does not stop it; a second load over the same year duplicates the work.

Troubleshooting

The year I need is not in the list

The year list comes from the source you chose, so a missing year means that source does not hold it. Pick the production source, or load the year's travel-time data first.

The task failed

The Error: line names the reason and the events show the step it reached; an incomplete year of travel times is the common cause. Fix the input and run the load again on the same dataset with Add Version.

The figures differ from the federal file

They are expected to differ slightly. The MAP-21 pages compute from the platform's dataset; the file filed with FHWA is fixed at submission and carries any corrections the validator required. See Uses and limits and Federal PM3 and what this site publishes.
