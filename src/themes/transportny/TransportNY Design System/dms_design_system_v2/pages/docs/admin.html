Admin.

Six procedures for the people who put data on the platform: uploading a dataset, curating it, building a map from it, putting that map on a page, rebuilding the MAP-21 and analytical datasets each year, and managing accounts. Everything here needs an administrator account. Readers need none of it.

hub applies to · all products last reviewed · 2026-09-08 owner · — requires an administrator account

Who this is for

NYSDOT staff and the platform team who administer the platform's data. You are in the right place if you upload files that become datasets, write the descriptions and column names the public reads, build the maps the products draw, or add and remove accounts. Every task on these six pages is invisible to a signed-out reader, and most of the controls do not appear at all until your account carries the permission the task needs.

If you only want the data, you are in the wrong hub. Read Download freight data for the catalog, the developer quick start for the API, and Download data from the Macro View for a measure export.

How authority works

Three things decide what you can do. First, you sign in, exactly as a reader would; see Sign in, sessions and accounts. Second, your account belongs to one or more groups, which is the only account attribute the Users page edits. Third, each dataset carries an Access list that grants named permissions — View source, Download source, Update source, Create version, Manage downloads, View source API, Delete source, Edit permissions, All (*) — to a group or to one person. A control appears when the permission behind it is granted and stays hidden when it is not, which is why two administrators can see different buttons on the same dataset. Users and permissions is the reference; each page below names the permission its task needs under Before you start.

noteThe earlier administrator guidance described three numeric authority levels — 1 view only, 2 view and download, 10 full access. The named permissions above are what this build grants and check; the mapping is on the users page.

What is not here

  • Not the pipeline code. The measures, the loaders and the yearly workers are code, not screens. These pages document the buttons that start them and the log that reports them. What the code does is on the datasheets in Measures & Data.
  • Not server administration. Hosts, storage, backups, deployment and the database are outside these pages and not documented here.
  • Not the command line. Every procedure here is the browser one. A command-line path exists for scripted loads; it is not documented here.
  • Not page authoring in general. One page covers the map section. Building the rest of a page, its filters and its cards, is not documented here.
  • No approval queue for sign-up requests. The Users page in this build adds an account by email; it does not list pending requests. See What these pages do not do.
