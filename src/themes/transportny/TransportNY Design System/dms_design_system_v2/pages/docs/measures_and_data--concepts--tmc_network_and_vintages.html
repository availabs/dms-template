The TMC network and its vintages.

What a TMC segment is, why there is a new map every year, which segment count to quote, what the enhanced network shapefile adds, and how segments are matched to OpenStreetMap and NYSDOT's linear referencing system. Written for analysts who compare years or build routes.

What a TMC segment is

A Traffic Message Channel (TMC) segment is the half-mile to two-mile piece of road that every probe record keys on. Every travel time in the feed names one TMC. Segments are direction-specific: a two-way road is two segments, one per direction. New York's current map holds roughly 52,000 of them. The median length is about 0.28 miles, and 24.3 % are under 0.05 miles.

A TMC is not a road. Corridors are chains of segments joined by the network attributes tmclinear (the linear road a segment belongs to), road_order (its position along that road) and direction. The TSMO Corridor View and the Congestion dashboard's corridor table are built on that chain.

One map per year, and two segment counts

The vendor re-cuts the TMC network every year. A segment can be split, merged, lengthened or retired between vintages, and a new segment can appear where none existed. The 2024 route analysis documentation put the consequence plainly: "The TMC network is updated annually and sometimes TMC segments change in length. It is good to check the TMC lengths before making any conclusions about behavioral change over time." That caveat still holds.

The TSMO Data & Methodology page counts 54,249 segments. That is a different quantity. Its network table accumulates every segment that has ever carried data, across all vintages, so a segment retired in 2020 still has a row. One year's map counts only the segments in that vintage. Both numbers are right; they answer different questions.

basisQuote the per-year count with its year: "52,157 segments on the 2025 map". Quote 54,249 only when you mean every segment that has ever appeared in the archive. A bare "52,000 TMCs" goes stale within a year.

A multi-year series is therefore not a fixed panel. The 2019 expansion added about 10,000 segments, most of them off the Interstate system, and the 2017 attributes come from a different family of network metadata that disagrees materially on functional class with 2018 to 2025. The coverage eras record both events because each moved the feed's completeness.

The enhanced network shapefile

The map the platform uses is not the vendor's file as delivered. The Data Manager describes it as "the enhanced TMC Network Shapefile that is built each time Raw NPMRDS data is processed into the Production database. This shapefile includes a variety of spatial datasets that provide additional network attributes (e.g., speed limits, MPO boundaries, NYSDOT region boundaries). This shapefile also calculates directionality from NPMRDS data for use in AADT disaggregation for the PHED measure."

So each vintage carries, per segment: geometry and length; road name, direction and cross-street; county and ZIP; functional system, National Highway System (NHS) flag and facility type; AADT with single-unit and combination truck AADT, and directional versions of each; the posted speed limit averaged from OpenStreetMap speed limits; NYSDOT region, MPO and urbanized-area codes; and the average vehicle occupancy PHED uses. The TMC network datasheet lists the columns. HPMS / RIS attributes covers where the roadway attributes come from and how they lag.

How segments are matched to OpenStreetMap and the LRS

NYSDOT keeps its own road network in a linear referencing system (LRS), and many programs report attributes into it. Using LRS data beside NPMRDS data is valuable and was hard, because the two geometries differ. The LRS is centreline, one line for both directions; TMC geometries are directional. The LRS also simplifies ramps, interchanges and traffic circles. Neither is a routable graph. A direct TMC-to-LRS conflation was tried and produced difficult edge cases.

OpenStreetMap (OSM) was chosen as the common base. Its network is built as a routable graph, represents ramps and circles accurately, and carries private roads, sidewalks and bike paths beyond the public roads the LRS holds. A growing set of tools and data providers publish on OSM links. SharedStreets, a linear referencing system designed to conflate other networks onto OSM and an evolution of TomTom's OpenLR, gave the method. Both TMC ids and LRS ids are mapped onto OSM geometry, so the three networks can be crossed consistently.

The process, as documented in 2024:

  1. Create a directional OSM file by adding a flipped geometry for every segment that is not one-way, with a direction flag (forward: true or false).
  2. Load the directional OSM data into the SharedStreets tool set.
  3. Use NPMRDS as input to SharedStreets to match each TMC segment to directional OSM segments.
  4. Use the LRS as input to SharedStreets to match each LRS segment to directional OSM segments.
  5. Use custom code to choose the correct match for each destination segment.
  6. Use custom code to split the output segments so each one ends where an input segment ends.
  7. Assign directional sections from LRS data, falling back on start and end orientation.

The output is a directional shapefile. Direction is recorded both in the attributes (dir, osm_fwd) and in the orientation of the line, so an offset draws both directions. Each output segment carries one OSM id, one LRS (RIS) id and one TMC id. Many output segments map to each source id, so selecting by id reconstitutes the source segment in OSM geometry. The published conflation table carries id, year, dir, n, osm, osm_fwd, ris, tmc, miles and the geometry. There is one conflation per network vintage.

How routes bind to a vintage

A saved route is an ordered list of TMC ids. It is therefore tied to the vintage whose ids it names. Route creation's marker mode, which auto-routes between dropped points, runs against the 2022 network and conflation version v0_6_0, pinned, because only 2020 to 2022 resolved in a live test near Albany in July 2026. The year shows as a static chip, not a select. A route drawn segment by segment names whatever ids the map shows. If a later vintage retires one of those ids, that segment of the route stops matching data. Check the segment list and its lengths before reading a route's trend across years. Routes data documents the saved fields.

Where this matters

Before you compare two years of any per-segment figure, confirm the segment exists in both vintages with the same length. Before you sum a network total, name the vintage, because the network grew from about 36,000 to about 52,000 segments over the archive. Quote 54,249 only for the accumulated table. Treat a route as a 2022-vintage object unless you know otherwise. When you need NYSDOT's own roadway attributes beside probe data, the OSM conflation is the crosswalk, and it exists per year. Coverage eras and comparability and AADT and its vintage cover the two other reasons a multi-year chart moves for reasons other than traffic.
