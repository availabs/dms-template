TMC network.

The enhanced TMC network shapefile: the geometry and attributes of every segment, rebuilt with each raw load and re-cut every year. The join backbone every measure keys to, and the owner of the two segment counts readers meet. For analysts and developers.

data applies to · all products last reviewed · 2026-09-05 owner · —

Overview

The TMC network is the spatial backbone. Probe travel times name a TMC id and nothing else; the network supplies the segment's line, length, road name, direction, county, region, functional class, AADT and speed limit. The Data Manager catalogues the current table as "NPMRDS TMC Network Shapefile - Enhanced V6": "the enhanced TMC Network Shapefile that is built each time Raw NPMRDS data is processed into the Production database. This shapefile includes a variety of spatial datasets that provide additional network attributes (e.g., speed limits, MPO boundaries, NYSDOT region boundaries). This shapefile also calculates directionality from NPMRDS data for use in AADT disaggregation for the PHED measure."

An earlier build, "AVAIL NPMRDS Shapefile Enhanced", remains in the catalog under Sandbox with a near-identical column set under abbreviated names. The TSMO Data & Methodology page names the current table's keys: "tmclinear · road_order · direction · county · miles · aadt · intersection", the fields that chain segments into corridors. The TMC network and its vintages explains the segment, the yearly map and the OpenStreetMap conflation.

Coverage and vintage

There is one network per calendar year, and two segment counts in circulation. A year's map counts the segments in that vintage. The accumulated network table counts every segment that has ever carried data, across all vintages. The TSMO Data & Methodology page's 54,249 is the accumulated count. Quote a per-year count with its year; quote 54,249 only for the whole archive.

The refresh cadence is "annual conflation"; the Data & Methodology page listed the 2026 network as current at its 2026-07-27 revision.

How it is produced

  1. Each raw NPMRDS load delivers the vendor's segment geometry and identification attributes for that vintage: road, direction, intersection, county, length, linear id, functional system, NHS, facility type, lanes, routes and AADT. The 2024 documentation states that "NPMRDS data includes traffic volume AADT data from FHWA", lagging about two years.
  2. Spatial joins add the NYSDOT region, MPO and urban-area codes from boundary layers.
  3. The average speed limit is joined from a table calculated from OpenStreetMap speed limits per segment.
  4. Directionality is calculated from the probe data and used to split AADT and truck AADT into this direction's share.
  5. The result is published as that year's network, and the segment-to-OpenStreetMap conflation is run per vintage. Speeds are joined to it live on the TSMO pages.

Uses and limits

Every measure joins to this table: the analytical series for geometry, length, functional class and AADT; PHED for directional AADT and occupancy; the excessive-delay series for the speed limit, AADT and region; Corridor View for the road order that stacks a corridor. Its limits follow from the yearly re-cut and the attribute vintages. A segment may not exist in every year or may change length, so check lengths before reading a trend. AADT carries its own revision cycle; see AADT and its vintage. A segment with no AADT or no speed limit carries no delay and is left uncoloured on a delay map. Map tiles carry only the row id, so popups look attributes up by segment afterwards.
