Users and permissions.

Give someone an account, put them in a group, send a password reset, and understand what a group's permissions let it do. Accounts are managed in one place; what an account may actually see is granted dataset by dataset. This page assumes your own account can open the Users page.

how-to applies to · all products last reviewed · 2026-09-08 owner · — requires an administrator account

Before you start

Sign in, then open Users or Groups from the platform's Auth menu, which also holds Profile. Each is gated separately, and without the right the page is not served. With no session, both read "To access this page, you need to login."

Understand the split first. These pages manage accounts and group membership and nothing else. What a person can see and do is granted per dataset, on its Admin tab, and per page in the page's settings. Adding someone to a group grants nothing by itself: it makes them eligible for what that group has been granted elsewhere. Each page on this hub names the permission its task needs, usually All (*) — level 10 in the earlier scheme.

Steps

  1. Open Users.Every account on this site: User (the email address), Groups, Created and Last Login, most recently active first. Empty Last Login means never.
  2. Find someone with search... in the User header, or list a group's members with filter group... in the Groups header.
  3. Add an account: Add new, the address in Enter user email, then Add.It reads "Adding" while the request is sent. The invitation carries this site's sign-in address, so send it from the site the person should use.
  4. Put them in a group: edit the Groups cell on their row.Adding assigns, removing takes them out. Make one change at a time — the row saves per edit.
  5. Send a password reset: reset password on the row, then reset at "Reset password for: the address?"They get an email linking to this site's sign-in page. You never see or set a password.
  6. To check what someone sees, select View As on their row, if your account may.It reads Viewing As and a bar shows "Viewing as:" with the address and groups; Exit View As stops it. Use it to confirm a grant before you say it is done.
  7. Open Groups.Two columns, Group and # Members, with search... in the first header.
  8. Add a group: Add new, the name at "Please enter Group Name", then Add.Name it for the organisation or role it stands for: that name appears in every dataset's access list from then on. A new group has no access to anything.
  9. Grant it what it needs on the dataset's Admin tab, from the table below.The grant takes effect immediately — check it with View As.

What a permission gates

A dataset's Access list grants named permissions to a group or one person. The nine, labelled as the panel shows them:

PermissionWhat it allows
View sourceSee the dataset: its Overview, its description, its column list, its table and its map
Download sourceDownload the data files generated for a version
Update sourceEdit the description, the categories, the update interval and the column metadata
Create versionAdd a version by uploading new data
Manage downloadsCreate and delete a version's download files, and cache its map tiles
View source APIRead the dataset programmatically. See Data Manager API
Delete sourceDelete a version, or the whole dataset
Edit permissionsChange this list — grant and revoke access to this dataset
All (*)Every one of the above

Three behaviours explain most surprises:

  • A control you cannot use is not shown. The pencils, Add Version and the Access panel appear only with the permission behind them, which is why two administrators describe the same page differently.
  • A dataset with no access list is open to any signed-in account. That is not the same as public. Grant the public group View source to make a dataset public, or name the groups that should have it.
  • A dataset's own list overrides the catalog's. A catalog grants a baseline; a dataset can replace or revoke it, and a newly uploaded one starts revoked.

The three earlier levels

The earlier guidance described access as one number per group: 1 view only, 2 view and download, 10 full access. Those levels are still the vocabulary people use, so each page on this hub names the level its task needs. The named permissions replaced them — View source is level 1, Download source adds level 2, All (*) is level 10 — and the middle is no longer a ladder: a group can have Update source without Delete source.

What these pages do not do

Four things administrators expect and will not find.

  • No queue of sign-up requests. The Users page lists accounts, not pending requests, and has no approve or reject action; an account is added by email with Add new. A site's sign-up form, where enabled, sends the same request to the authentication server; where disabled it reads "Sign up is not available. Please contact an administrator." The deployed TransportNY build carries the same code, so its Users page shows no queue either (checked 2026-09-08).
  • No authority number on a group. The Groups page names a group and counts its members; grants live on the datasets and pages.
  • No way to delete an account. To take away access, remove the person from every group and revoke any grant made by name; the account remains.
  • No names, roles or organisations. An account is an email address and a set of groups, so the group carries any meaning you need.

Limits and gotchas

  • The list is per site, so someone working in two products may hold two accounts, and an invitation points at the site you sent it from. See How long a session lasts.
  • A group's name is load-bearing: renaming is not offered, and every access list naming it would have to change.
  • Granting access does not put a dataset in front of anyone — a reader still needs a page or the catalog to find it.
  • A permission change reaches someone's browser when their page next loads, not the instant you save it.

Troubleshooting

Someone says they cannot see a dataset

In this order: are they signed in on the right site; which groups does their row show; does the dataset's Access list name one of those groups with View source? Then confirm with View As.

I added someone and nothing changed

Adding an account grants nothing. Put them in a group, then make sure that group appears in the access list of whatever they need — a new group has none anywhere. If the Users page itself will not open, your session expired or your account lacks the user-administration right.
