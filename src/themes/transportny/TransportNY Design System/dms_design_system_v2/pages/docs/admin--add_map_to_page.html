Add a saved map to a page.

Put a map section on a page, choose the saved map and the layer it opens on, set its height and legend, optionally tie it to the page's own filters, and publish. At the end readers see the map you built in the editor. This page assumes the saved map exists.

Before you start

Build the map first — Build a map in the Map Editor — and note its name.

Open the page and enter edit mode; its address gains /edit/. You need authority to edit the page, and publishing needs the publish right on it: All (*) covers both, the earlier scheme's level 10. Without the publish right the button at the foot of the edit panel does not appear and your changes stay a draft.

Decide two things first: whether readers switch layers themselves, which decides the Layer Library Panel, and whether the map follows the page's filters, which decides whether you touch Page Variable Bridge.

Steps

  1. Hover the gap where the map should go and select Add.An empty section appears with its own Settings menu.
  2. Open Settings › Type and choose Map.The section becomes a map at the default view of the state, and the menu gains Map Settings.
  3. Open Map Settings › Symbologies, which reads "No symbologies yet — add one below."
  4. Under Add symbology, find your saved map with Search available symbologies… and select Add to map.It joins On this map, switched off: "Added hidden — toggle it on above. A second symbology puts the map in multi-symbology mode."
  5. Switch it on in On this map.The map draws. The first visible entry is marked active and is the page's primary map.
  6. If the saved map has several layers, pick the one it opens on from Active layer….The active layer is also the one a filter zooms to, so choose the geography that should frame the map.
  7. Add further saved maps the same way. With more than one, turn on Layer Library Panel so readers can toggle them, and give each a Category to group it there.With the panel off: "Symbologies render as configured; viewers get no toggle panel."
  8. Open Map Settings › Display and set Height, Legend Position and Zoom/pan.A map with zoom and pan off is a picture — a figure, not a tool.
  9. Frame it: either turn on Zoom to Fit, or turn on Set initial viewport and save the view you want.
  10. Optional: open Map Settings › Filters › Page Variable Bridge, choose the map's row, turn on Use Page Filters, and set Page Variable Key to the page variable that drives it and Layer Field to the tile column it filters on.The map now follows that filter: pick a region and it draws only that region.
  11. Set the section's place from Settings › Layout: Width for the column span, Style for the band.
  12. Select Publish in the edit panel.It reads No Changes when there is nothing to publish, and Discard beside it throws the draft away. Readers see the map only after this step.

Keeping a page's map in step

A page does not point at a saved map; it holds a copy. That is deliberate — a restyle cannot break a published page by surprise — but a page can drift. To bring a restyle across, open the page's Map Settings › Symbologies, select the refresh control on the map's row ("Sync this symbology with the latest editor changes"), then publish: it merges the editor's version over the copy and keeps the page's own visibility, active layer and filter bindings. The remove control ("Remove from map") takes the copy off the page, not the saved map.

cautionA link that opens a map with certain layers switched on can only name maps the section holds — unknown ones are ignored by design. In July 2026, 9 of 22 gallery tiles opened the Freight Atlas map with only part of their preset for that reason. If a preset link comes up short, check On this map first.

Limits and gotchas

  • The section keeps a copy: nothing in the editor reaches a page until that page is refreshed and published, and nothing on a page changes the saved map.
  • A map filter can only follow a page variable the page has declared. A value another card publishes on click is not one, so bind both to the same page variable instead.
  • A filter's values must match the tile column's exactly. Point the page's filter control at the same dataset the layer draws and one vocabulary serves both.
  • On a very large per-row dataset a filter runs after the whole tile downloads, slowly enough to look broken; those layers need the filter applied on the server, which is not a control here.
  • Check the page with no address parameters before publishing: a page variable that is declared but unset must widen the map to everything, not blank it.

Troubleshooting

The section is blank

Either no saved map is switched on in On this map, or the one that is has no visible layer. Switch it on, then check Active layer…. If it still draws nothing, open the map in the editor and confirm it draws there.

The map lost its colours when a filter was set

The filter names a column the tiles do not carry, so the layer has nothing to draw. Bind it to a plain column of the dataset the layer draws, kept for the map at upload.

Readers see the old map

Two causes, in this order: the page's copy has not been refreshed, which is the map's row in Symbologies; or the page has not been published, so the edit panel's button still reads Publish.
