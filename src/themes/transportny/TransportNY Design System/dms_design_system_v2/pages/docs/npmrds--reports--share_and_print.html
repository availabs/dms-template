Share, print and publish a report.

A report's header carries four actions: Data, Share, Print and Edit. Sharing is the address, printing is the browser's, and publishing happens when the author selects Done. What each does, what a reader sees, and why a link is not a citation.

how-to applies to · NPMRDS last reviewed · 2026-09-05 owner · —

Before you start

Open any report. Reading, sharing and printing need no account. Publishing needs the report to be yours and you to be signed in. The header shows, top to bottom, an All reports back link, a kicker line with a published or draft pill, the title and purpose, the action buttons, and a data line reading complete through a month.

Steps

  1. Select Share.The page's address is copied and the button reads Copied for a moment. Paste it anywhere; anyone can open it.
  2. If the report was opened from a template, keep the whole address. The part after ? holds the routes you picked (routes=) and the anchor date (asOf=); without it the recipient is asked to pick routes again.
  3. Select Data to open the download the author linked.It opens in a new tab. The button is present only when the author set a Data link.
  4. Select Print.The browser's print dialog opens. Choose a printer or save as PDF. Landscape suits the wide cards. The report has no print stylesheet of its own yet, so the printed page is the reading page as the browser lays it out.
  5. To publish changes, select Edit, make them, and select Done.The pill turns from draft to published and the reading address shows the new graphs.
  6. Before you send a number on, write down the address, the date you read it and the data line's complete through month. See below for why.

What a reader sees

Readers see the published page: header, graph cards, no Routes rail and no pills. Route changes made in the rail reach readers as soon as they are made, because routes are stored with the report and read live; new graphs, header text and layout appear only after Done. A draft report, one never published, still has a reading address, but its graphs are whatever was last published there.

The address as a citation, and its limits

The address reproduces the view: the report, and for templates the routes and anchor date. It does not freeze the numbers. Graphs recompute from the data on every open, so a later data revision, a newly loaded month, or an author's edit changes what the link shows. A template anchored to the latest available date drifts forward every month. For a figure you must defend, download the data behind it through Data where the author provided it, or export the measure from the Macro View, and cite the address with the date you read it and the complete through month.

Limits and gotchas

  • Done is publish. There is no separate publish button on a report and no way to leave edit mode without publishing.
  • Data points wherever the author pointed it. It is not generated from the graphs.
  • A report cannot be made private. Every report address is public to read.
  • NPMRDS runs on its own subdomain, so a link from another product may ask a signed-in user to sign in again. Reading does not require it.

Troubleshooting

Share did nothing

The browser refused clipboard access, which happens on an insecure connection or when permission was denied. Copy the address from the address bar instead.

The printed page is missing graphs

Let every card finish loading before you print, and use landscape. If a card is still blank on screen, reload once; a card can render empty right after a change is published.

A colleague was asked to sign in to open my link

Reports are public to read. If the link came from an /edit/ address, send the reading address without /edit/. If a plain address still asks, report it; the same problem was recorded against the earlier tool in May 2026.
