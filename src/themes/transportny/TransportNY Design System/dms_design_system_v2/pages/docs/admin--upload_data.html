Upload a dataset.

Create a source, upload a GIS or tabular file, decide what its columns are called, and publish it as the source's first version. At the end you have a dataset page with a description, a column list and one version, ready to curate, map or download. This page assumes you have a file and an administrator account.

Before you start

Sign in and open the dataset catalog — Data & Downloads in the Freight Atlas, or the catalog entry in the product you administer. Creating a dataset needs All (*) or the create right on the catalog: full access, level 10, in the earlier scheme. The Add control shows for any signed-in account, but the page it opens is refused without that authority.

The upload accepts .csv, .tsv, .xlsx, .xls, .shp, .gpkg, .geojson and .json, alone or inside a .zip, from which the first supported file is loaded. A Shapefile must be zipped, being a set of files.

Decide the type first — it cannot be changed afterwards. GIS files get geometry a map can draw; tabular files get columns a table or a graph reads.

Steps

  1. Select Add in the catalog toolbar.The Create Dataset page opens.
  2. Open Type and choose gis_dataset for geometry or csv_dataset for a table; The data types on offer lists the rest.The Create button is replaced by that type's upload panel.
  3. Enter the name readers will see in Name, as a title. Until you do the panel reads "Please enter a datasource name."
  4. Select the file chooser and pick your file.A File Metadata table appears with Name, Last Modified, Size and File Upload Status, which runs from "Sending GIS File to server" to "GIS File Analysis Complete". Stay here.
  5. Choose the layer in Select Layer. Only one loads at a time, so a file with two layers needs two datasets.Layer Analysis counts the features per Geometry Type under Feature Count, after reading "Analyzing Layer... please wait."
  6. Check Field Names Mappings: each row pairs an Upload File Columns entry with the Database Column Name it is stored under. Keep those lowercase, underscored and recognisable a year later; display names come later, on the metadata page.
  7. Tick Omit on any column you do not want loaded — a duplicate, an unusable field, anything identifying a person. The header checkbox omits every column at once.
  8. Tick Mbtile on the columns a map will draw or label with: it decides which values travel with the map tiles.
  9. Select Publish.The button reads "Publishing..." and the page moves to the source's Upload Views list, which is the load's own log.
  10. Open this load's row and read its events — Id, Event Type, Timestamp. When Event Type reaches FINAL the data is in; a load that stops short of it failed, so see Troubleshooting.
  11. Open Overview and check that Columns counts what you expected and Versions holds one version.
  12. Write the description, the column display names and the download files before you tell anyone it exists — all on Manage a dataset.
cautionA new dataset is private: its creator has every permission and nobody else has any. Grant access on the Admin tab — see Access and deletion.

What you now have

A dataset with one version, an Overview tab and, for a GIS dataset, Table and Map. Nothing is downloadable yet, and nothing is on a page — those are the Map Editor and adding a map to a page.

A flat file instead of a dataset

A PDF, an image or a download bundle has no columns. Choose file_upload as the Type, enter a name of four characters or more, and select Select a File. The panel shows File Info, an optional Directory Path: and a Description:; Upload File then makes the file a version, served from Versions with a Download button. Very large bundles can be refused by the server in front of the platform.

The data types on offer

The first four are generic. The rest run a named pipeline over data already on the platform, with their own inputs instead of a file.

Limits and gotchas

  • One layer per dataset: a file with several layers or sheets needs one upload each.
  • Do not leave the page between the file and Publish: the staged file is cleaned up between sessions, and a late publish fails.
  • A version must carry the dataset's columns. Data that has changed shape needs a new dataset.
  • Column types are guessed. Identifier columns in a tabular file — codes such as 31-33, ids with leading zeros — are read as numbers and refuse to load.
  • A failed publish can leave the dataset with no version. Add a version to that one rather than making a near-duplicate.

Troubleshooting

The file was refused

"Unsupported file type" means the extension is not one of the eight; convert the file. "No supported data file found in archive" means the zip held nothing readable — often a Shapefile missing its parts — so rebuild it around the data file, with your system's own zip tool. A GIS file can also be refused because the server's geospatial library is unavailable, which the message says: report that one.

The log stops before FINAL

The load failed. The event list names the step, not the reason. Check the two common causes — a numeric column holding text, a staged file that expired — then report it with the load's id.
