Read an incident page.

One event end to end: what it was, how the response was recorded, how much delay it added and where, and its place on the map. How to get there, how to read each panel, and what a map with a pin but no segment means.

how-to applies to · TSMO (www/tsmo) last reviewed · 2026-09-05 owner · —

Before you start

The incident page, titled Incident View, is not in the side navigation. Reach it from a result row's view link in Incident Search, or from the Recent & major events table on the Incidents dashboard Each row carries a view → link that opens the incident page.. The address carries the event id, so the page can be shared.

Steps

  1. Read the header: the event's facility, category, and when and where it happened. The Event facts card carries identity, lanes and location straight from the TRANSCOM record.
  2. Read Location & affected segment. Two layers: Event location, a pin, and Affected segment, the segments that carried delay.A pin with highlighted segments means a measured footprint. A pin alone means no affected segments were recorded for this event.
  3. Read Response timeline. Its steps are the Traffic Incident Management (TIM) timestamps: reported, verified, response on scene, all lanes reopened. Only a recorded timestamp gets a check; a missing step is muted not recorded. Nothing is interpolated.Across the feed, all-lanes-reopened exists on 42.7 % of events, verified on 20.1 %, reported on 10.6 %, response-on-scene on 0.3 %. Expect gaps.
  4. Read Congestion footprint: the delay this event added above the recurrent baseline, in vehicle-hours, its cost at an interim $20 per vehicle-hour, and the count of affected segments.
  5. Read Corridors. Delay is rolled up by corridor and each corridor is labelled by its road names. The highlighted row is the page's active corridor, which defaults to the corridor carrying the most delay.Select another row to make it the active corridor. The per-segment table and the grid re-scope to it.
  6. Read the per-segment table. One row per segment of the active corridor, in road order upstream to downstream, labelled by segment and cross street.
  7. Read Congestion grid. Rows are the top 20 segments by delay; columns are 5-minute slices across the affected window. A coloured cell means the segment was inside its affected window then, shaded by attributed delay.You can see when and where the queue formed. A speed-against-free-flow version of the grid is not built.
  8. Read How one incident is measured, the method note at the foot of the page.

Limits and gotchas

  • About 18.5 % of events have a footprint. For the rest the footprint panel, the corridors and the grid have nothing to show.
  • Duration on the event is an estimate entered at the time, clustered at round values.
  • Cost is the interim flat $20 basis. See Which pages show which basis.
  • A list of nearby or similar events was removed in July 2026.
  • The feed is multi-state. An out-of-state event has no New York segment to match, so it can never have a footprint.

Troubleshooting

The map shows a pin but no segment

No affected segments were recorded for this event. The map centres on the pin instead. At a measurement on 2026-07-28, 77.5 % of events since 2026-06-01 had no footprint, and part of that share was out-of-state events. It is not a broken map.

The timeline is mostly "not recorded"

Most events carry few TIM timestamps. The page shows only what exists. Clearance measures on the Incidents dashboard are computed on the timestamped subset and badged with its size.

The corridors table and grid are empty

The event has no footprint, so there is no delay to roll up. Check the footprint panel: it shows a dash.
