NPMRDS travel times.

The probe travel-time table every other number on the platform derives from: one row per segment per 5-minute epoch, three vehicle streams in the row, since January 2017. The datasheet for analysts and developers who want the raw feed or need to know what it does not contain.

data applies to · all products last reviewed · 2026-09-05 owner · —

Overview

The National Performance Management Research Data Set (NPMRDS) is the Federal Highway Administration's (FHWA) licensed feed of probe-vehicle travel times. New York's extract covers the National Highway System (NHS) plus the expanded network NYSDOT licenses beyond it. The Data Manager catalogues the platform's copy as "NPMRDS Production V6" and describes it as "the main table of NPMRDS data which is updated weekly. This data is Epoch-level travel times for TMCs and it combines the all-vehicles, passengers, and trucks into one row per TMC-Epoch."

One row is one TMC segment in one 5-minute epoch. It carries up to three travel times, for all vehicles, passenger vehicles and freight trucks, and a data-density code for each. The streams arrive independently; a row can have an all-vehicle value and no truck value. The 2024 documentation names the provider as INRIX via the CATT Lab at the University of Maryland, with HERE supplying 2016 to 2018.

basisCounts on this page are statewide, the full monitored network, all three streams, with the date of the count in each sentence.

Coverage is not stationary. Daytime epoch coverage moves in nine month-aligned eras between 2017 and 2026, from 28.0 % to 67.0 %. Across the published years, all-vehicle bins reporting runs 36.3 % to 51.5 % and truck bins 8.0 % to 23.5 %. 88.1 % of records rest on four probes or fewer, and trucks are absent from 59.6 % of records. Coverage eras and comparability carries the era table. The segment set changes every year with the map; see TMC network.

Schema

The stored columns, from the Data Manager's column list. The catalog also exposes derived query fields (earliest and latest date, year, month) that are not stored columns.

FieldTypeSample valueDescription
tmcstring120N14364The TMC segment id the observation keys on; one direction of one road piece.
datedate—Calendar date of the epoch.
epochinteger—The 5-minute slice of the day, 288 per day. Numbered 0 to 287: epoch 0 is 00:00–00:04, and the hour is the epoch divided by 12.
travel_time_all_vehiclesnumber—Travel time across the segment for all probe vehicles, in seconds, recorded to 0.01 s. Absent when no probe reported.
travel_time_passenger_vehiclesnumber—Travel time for the passenger-vehicle stream, in seconds.
travel_time_freight_trucksnumber—Travel time for the freight-truck stream, in seconds. Absent on 59.6 % of records.
data_density_all_vehiclesstring—The vendor's density code for the all-vehicle stream, a coarse indicator of how many probes fed the value. Codes A, B and C: A for 1–4 probe vehicles, B for 5–9, C for 10 or more, per the NPMRDS data specification; most records carry A.
data_density_passenger_vehiclesstring—Density code for the passenger stream.
data_density_freight_trucksstring—Density code for the truck stream.
statestringNYState of the segment. Seconds, recorded to 0.01 s; sub-second values on very short segments are correct.

A missing travel time means no probe reported on that segment in that epoch. The platform stores nothing in its place and does not interpolate. Read a blank as "not observed", never as zero.

How it is produced

  1. Raw NPMRDS files are downloaded from the RITIS system. Each download is kept as a version of the raw-downloads source, so a load can be traced to the file it came from.
  2. The raw data is processed into the production table. Each processing run also rebuilds the enhanced TMC network shapefile for that vintage.
  3. Nothing is imputed and nothing is dropped by the platform. The feed arrives already filtered upstream: zero of 1,695,358,623 CY 2025 records fall below 2 mph, and the maximum implied speed is 101.7 mph, with 99 records above 100 mph and a 7,700-fold drop at that boundary. What the upstream clamp removed cannot be audited from this side.
  4. Downstream, the Macro View measures average epochs into 15-minute bins; the TSMO excessive-delay series reads 5-minute slices; Corridor View joins epochs to the network live. See Peak periods and epochs.

Sub-second travel times are correct, not corrupt. 8,292,469 CY 2025 records (0.489 %) are under one second, all on segments shorter than 0.05 miles; a 53-foot segment at 38.5 mph legitimately takes 0.94 s. A relative epoch screen that removes readings extreme for their own segment and isolated in space and time is planned and not yet applied.

Uses and limits

This table feeds everything: the MAP-21 dataset and the analytical series are built from it by selecting a year, the excessive-delay series reads its 5-minute slices, Reports and Route Comparison chart it per route, Corridor View replays it. Its limits are the platform's limits. Coverage moves in eras and biases reliability up and delay down when thin. Overnight is the thinnest period. The truck stream is sparse enough that TTTR cannot meet its precision bar on any segment. The slowest readings are clamped before arrival. Very short segments produce sub-second times and fragile percentiles. None of these is fixed by the platform; each is stated beside the measure it affects.

Distribution

  • Macro View download. The CSV or GeoPackage package carries computed measures per segment and year, with coverage and era columns and a PM3_README.txt. It does not carry raw epochs. See Download data from the Macro View.
  • Data Manager. The source page lists the table's versions, columns and metadata. Whether the source page offers a raw epoch extract is not documented; the documented routes to the data are the Macro View download and the Data Manager API.
  • Data Manager API. The same endpoint the dashboards render from. A key is issued on sign-in; the public allowance is 10,000 requests per day. See Data Manager API.
