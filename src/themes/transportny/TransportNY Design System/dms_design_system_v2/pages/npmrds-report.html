// 03 the rail above is live · states are reached, not drawn

Drive it, then read this.

Hit Edit in the page header, open a route, and the whole control set is there. Both modals are reachable either way — the two Add buttons never hide. This band is the reference: what each control writes, and why the design landed where it did.

// try this
Every state, in nine clicks.
  1. 01Type I-84 in the rail's search — the no-match state, then clear it.
  2. 02+ on any route — the open-out: the window, the day/time restriction, the graph chips.
  3. 03Nothing in the rail is behind a mode — reorder, rename, remove, colour, window and assignment are always live. Edit in the page header adds the page chrome instead: a section toolbar per card, the Measure Picker, the Dynamic Report switch. The graph cards deliberately don't move — see the note below.
  4. 04Rename a route to a name another route already has — the refusal is real copy, not a placeholder.
  5. 05Pencil beside window → three facets in the order the engine applies them: dates (which days, with the count it will really enumerate), days (which of those count), time of day (which hours of each one). Set the end time earlier than the start to see the silent-failure warning.
  6. 06Copy a window, then paste into all from the strip that appears at the top of the rail — or paste it route by route. Derived-date routes are skipped and say why.
  7. 07The colour dot on any row → the colour popover, no need to open the route; a chip → assignment on/off. Open NY-9D SB · after: its dates are derived, so it says so instead of offering a pencil.
  8. 08Add route → search leads; the County / Region / Agency doors sit beside it. Drill in, come back on the breadcrumb, search inside a tag, watch already-added routes get flagged. Every row carries its own tags, so two routes with the same name stem are still tellable apart.
  9. 09Add graph → pick a shape from the five cards (Bar · Line · Grid · Table · Map), then a value from the grouped measure list; resolution and comparison mode are demoted to refine. Set Difference and check exactly two routes to make the Anchor Route select appear. The footer names what will be built — including whether it's an AVL Graph, a Spreadsheet or a Map.

Inert on purpose: the two confirm buttons, remove, duplicate and the section Settings drawer. Adding or removing would change the report; this page designs the flow, not the write. Colour and assignment edits move the rail's own chrome — the plots are still drawings and don't redraw.

// rules this set forced
A 340-px control surface.
  • 01A control has to describe the query it builds. The window read “start date + start time / end date + end time”, which claims a continuous stretch between two instants. The engine builds a list of days and, separately, a band of hours applied to every one of them — it averages the same hours across days. Three facets in the engine's own order (dates → days → time of day) say that; the old pairing said the opposite, and no amount of polish fixes a control that lies about its result.
  • 02Name the silent failures. A backwards time window empties the epoch list, and an empty list means the filter is never sent — so it silently returns all-day data. The control says so, in those words, rather than letting a plausible-looking window produce a wrong chart.
  • 03If every route wants the same value, make it copyable. A before/after report is four routes with one window. Retyping four fields per route is a transcription-error generator, so the window copies as one shape and the copied strip offers the bulk case first.
  • 04Two affordances per row, never more. Rename and remove sit in the row; everything else waits inside the open-out. At 340 px a row with six icons is unreadable and the route's name — the thing you scan for — loses its width.
  • 05Editing is explicit; saving isn't automatic. The name and the window each take a save/cancel pair, because a half-typed window would refetch every graph on the page. Colour and chips commit on click — single, reversible, cheap.
  • 06Presets before fields. AM Peak and Weekdays are the real vocabulary; the raw inputs stay, but nobody should have to type 16:00 twice from memory. The two windows that wrap past midnight are absent on purpose — the epoch range can't express them.
  • 07Destructive is the only coloured control. Amber = you are editing; rose = removal; blue = the one primary action. Nothing else earns a colour, which is what keeps the route colours themselves legible.
  • 08Colour is a popover on the dot, not a block in the open-out. Inline it was doubly buried — expand the route, then click “change” — for a control whose whole job is “this route is blue everywhere”. You notice two routes are hard to tell apart while looking at a chart, and from there it's one click on the dot. The TMC list left the open-out for the opposite reason: nobody identifies a route by reading 120P29714 off a rail, so the count in the meta line is the useful part.
  • 09Say “unused”. A route on no graph is a half-finished report, not a tidy one, so the row says so and the empty-state card in the canvas repeats it by name.
  • 10Nothing in the rail hides behind a mode. Add Route and Add Graph sit in an always-present action row, and every per-route control — window, colour, name, order, assignment — is live: a report with no routes has to offer the way out of that state, and a mode you have to discover first is not an offer. Page edit mode still governs the page: section toolbars, the Measure Picker, Dynamic Report.
  • 11Don't fake the refetch. A route's window, colour and assignment do publish to every card the route feeds, and in the product those cards redraw. This page has no data behind it, so it doesn't pretend: the cards stay the drawings they are, and the binding is written down rather than simulated. A version that rebuilt legends and flashed “updating” was reverted — it made cards look refreshed while the numbers underneath hadn't moved, which teaches the wrong thing more effectively than saying nothing.
  • 12The panel scrolls once. The head, the action row and the totals are pinned; only the rows move. A rail that scrolls as a whole loses its Add buttons exactly when a long list makes you want them.

// what changes on paper
Chrome is not content.
  • 01Drop every affordance. SideNav, the ds-nav widget, quick-control pills, kebabs, Edit, Share — none of it survives a PDF, so none of it prints.
  • 02Promote the finding. On screen it is a canvas section under the header (it left the rail when the rail became a control surface); on paper it leads, because a printed report is read linearly and often only page one.
  • 03The rail becomes a legend. Route colours still key the charts, so the rows persist as a static colour key — without the mutation controls.
  • 04Provenance and pagination move to a page foot. The per-card attribution lines collapse into one sheet-level line — the same facts, once.

Scope note: this is one drawn state, per Open question 4's recorded default. A real print stylesheet — page breaks that never split a card, repeated headers, widow control — is its own task.
